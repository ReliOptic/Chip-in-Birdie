# 편집 기준

[채널 공식](../FORMULA.md)의 여섯 항을 한 편에 적용하는 방법이다. 관객 정의는 [채널](../channel/CHANNEL.md)에 있다.

## 1. 패키지 먼저

대본 전에 아래 세 가지를 한 장에 놓고 서로 맞는지 본다.

**제목 (영어, 3안)**
- 사건이 식별된다. 고유명사나 구체 사물이 하나 들어간다.
- 긴장이 한 군데 있다: 어긋남, 대가, 뜻밖의 결과.
- 검증된 사건 범위를 넘지 않는다.
- 쓰지 않는 것: 맥락 없이는 뜻이 안 통하는 문구, 긴 why-질문, 의미 없는 큰 숫자.
- 한국어 검토 제목은 번역이 아니라 따로 자연스럽게 쓴다.

**썸네일 (2안)**
- 시청자가 실제로 보게 될 물체·상황·관계 하나.
- 제목 문장을 반복하지 않는다. 글자는 3단어 이하.
- 휴대폰 크기에서 주제가 읽힌다.

**첫 30초**
- 0–10초: 패키지가 약속한 사건의 한 장면. 누가 무엇을 원하는지 보인다.
- 10–30초: 무엇이 걸려 있는지, 무엇이 이상한지.
- 정의·연혁·채널 소개·"오늘은 ~를 알아봅니다"로 시작하지 않는다.

## 2. 비트 구조 (510초 기준)

| 구간 | 할 일 |
|---|---|
| 0:00–0:30 | 사건과 긴장 |
| 0:30–2:00 | 상황: 당사자, 원하는 것, 막힌 것 |
| 2:00–4:30 | 기술 조건: 이 사건에 필요한 메커니즘 하나를 상태 변화로 보여준다 |
| 4:30–6:30 | 선택: 당시 대안, 제약, 누가 비용과 위험을 졌는가 |
| 6:30–8:00 | 결과: 돈·시간·조직·관계에서 달라진 것 |
| 8:00–8:30 | 회수: 처음 사건이 다르게 읽힌다. 다음 편 하나를 가리킨다 |

이야기가 요구하면 순서를 바꾼다. 어느 구간이든 90초 안에 질문이 한 칸 전진해야 한다.

## 3. 피곤한 관객을 위한 규칙

- 한 장면에 새 개념 하나. 용어는 화면의 물체나 행동에 붙인다.
- 개념을 설명하기 전에 그 개념이 푸는 문제를 먼저 보여준다.
- 비교할 때는 바뀐 값과 그대로인 값을 화면에서 구분한다.
- 수치·표·지도는 읽을 시간을 준다.
- 당사자 누구도 바보나 악당으로 만들지 않는다. 후대의 성공을 당시 결정의 필연으로 쓰지 않는다.

## 4. 영상·사운드

- 사건에 맞춰 사료·실사·2D·3D·시뮬레이션을 고른다. 3D는 공간과 상태 변화를 설명할 때 쓴다.
- 상태 변화가 필요한 설명을 정지 화면과 자막으로 대신하지 않는다.
- 내레이션·효과·음악을 분리한 채로 음량·발음·자막을 함께 검수한다.

## 5. 리뷰 판정표

편집 리뷰, 모의 시청자 리뷰, 브리프가 모두 이 표를 쓴다.

| 질문 | 통과 | 차단 |
|---|---|---|
| 왜 보나? | 제목·도입에서 사건과 긴장이 드러난다 | 이해하고 싶은 일이 없다 |
| 무슨 일인가? | 비전공 검토자가 사건을 자기 말로 설명한다 | 행위·물체·시간 순서가 불명확하다 |
| 계속 궁금한가? | 각 구간이 질문을 전진시킨다 | 반복·긴장 없는 정보로 사건이 멈춘다 |
| 왜 그렇게 됐나? | 기술 조건과 결과가 화면에서 이어진다 | 용어 나열과 자막이 원인을 대신한다 |
| 누가 무엇을 골랐나? | 대안·제약·대가가 근거와 연결된다 | 천재·악당으로 축약, 결과의 소급 |
| 무엇을 얻나? | 처음 사건이 새 맥락에서 읽힌다 | 일반 교훈이나 구독 요청으로 끝난다 |
| 다음 편도 볼까? | 다른 소재에서도 같은 보상이 기대된다 | 특수한 현업 지식에만 의존한다 |

차단 항목이 하나라도 있으면 반려한다. 점수 합산으로 통과시키지 않는다. 반려에는 위치·문제·영향·수정안을 적는다.
