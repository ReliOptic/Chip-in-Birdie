# 261127 | 한국어 표현과 논리 기준

2026-11-27 CUDA 플랫폼 발표 자료를 만들며 받은 사용자 지시를 정리했다. 그날 반복해서 고친 문제를 채널 대본, 자막, 제목, 한국어 발표 자료, 보고 문서 모두에 적용할 수 있게 일반화한 것이다. [PLAYBOOK](PLAYBOOK.md)이 "무엇을 왜 보여 주는가"를 다룬다면, 이 문서는 "그것을 어떤 말과 순서로 쓰는가"를 다룬다. 영어 정본에도 논리 기준(비약·비유·사실과 해석 구분)은 그대로 적용한다.

예시의 "고치기 전"은 실제로 반려된 문구, "고친 뒤"는 받아들여진 문구다.

## 1. 비유로 설명을 대신하지 않는다

비유는 검증할 수 없다. 청중은 메커니즘 대신 이미지를 기억하고, 근거 없이 그럴듯한 말은 할루시네이션처럼 들린다. 사실 문장으로 바꿔 쓴다.

| 고치기 전 | 고친 뒤 |
|---|---|
| AI가 코드의 국적을 지운다 | AI 코드 변환과 전환 비용 하락 |
| 코드 대신 모델을 쥔다 | 인수 전후 비교 |
| 그래픽 명령으로 위장한 계산 | (장면 삭제) |
| 수요는 코드에서 나왔다 | 개발자 코드 축적과 GPU 수요 |

## 2. 제목은 앞 내용에서 이어지는 사실을 짧게 쓴다

- 제목은 앞 장면이 근거를 보여 준 결론만 말한다. 근거 장면 없이 결론을 먼저 던지면 비약이다.
- 질문형 제목, 수사 의문문, 극적 대구("묶지 않고도 지배할 수 있는가")를 쓰지 않는다.
- 발표 자료의 제목은 짧은 명사구로 쓴다. "~다/~였다"로 끝나는 서술형 문장으로 쓰지 않는다. 결론 문장은 부제나 시사점 상자에 둔다.

| 고치기 전 | 고친 뒤 |
|---|---|
| 129억 달러를 쓰는 이유 | 허깅페이스 인수 배경 |
| 인수 금액 129억 달러는 FY2026 매출의 6%다 | 인수 규모 |
| 매출은 65% 늘었고 매출총이익률은 70%대를 지켰다 | 매출 성장과 수익성 |
| 기존 플랫폼 접근은 무너지는가 | 고착형 플랫폼 전략의 지속 가능성 |

## 3. 중립적으로 쓴다

- 소설·드라마 톤("벽에 틈이 생겼다", "길이 열렸다")과 연출용 라벨을 쓰지 않는다. 섹션 이름은 다루는 대상을 그대로 적는다.
  - 고치기 전: 커뮤니티 효과 > 코드에 묶인 독점 > AI가 연 길 > 플랫폼 재편 > 투자 논리
  - 고친 뒤: CUDA 생태계 > 시장 지위 > AI 코드 변환 > 허깅페이스 인수 > 인수 배경
- 도구를 의인화하지 않는다. "AI 에이전트가 코드를 이식한다"가 아니라 "AI 기반 코드 변환", "자사 AI 모델로 변환"으로 쓴다.
- 강의조, 번역투, 훈계조를 쓰지 않는다. 청중이 모르는 고유명사를 나열하지 않는다. 필요하면 범주로 묶어 쓰고, 이름은 근거 칸에 둔다.

## 4. 업무 용어를 쓴다

구어나 유아적 표현은 전문 청중에게 신뢰를 잃는다. 경영·재무 맥락에서는 그 분야의 용어로 쓴다.

| 고치기 전 | 고친 뒤 |
|---|---|
| 돈을 쓴다, 자리를 산다 | 투자, 인수가, 확보 |
| 가격을 거의 내리지 않았다 | 가격 결정력 유지 |
| 옮기기 어렵다는 점이 해자였다 | 높은 전환 비용이 해자 |
| 보유하는 층이 넓어진다 | 사업 영역이 모델 유통으로 확장 |

## 5. 화면 글과 말하는 글을 나눈다

- **화면 (발표 자료, 자막 카드):** 제목, 부제 한 줄, 개조식 본문으로 쓴다. 본문은 명사형으로 끝낸다(예: 확보, 유지, 제한, 확대). 기준은 4-2조 덱 *NVIDIA Blue Ocean Strategy v2*(2026.5.20)다. 그 덱처럼 카드마다 굵은 소제목과 근거를 함께 둔다.
- **말 (대본, 내레이션):** 합쇼체로 쓴다. 한 장에 2~4문장이다. 앞 장의 결론을 받아서 시작한다.
- 화면에 면책 문구, 단축키 안내, 사용 설명을 넣지 않는다. 상태는 모양, 위치, 움직임으로 전달한다.

## 6. 장과 장은 인과로 잇는다

- 각 장의 결론이 다음 장의 전제가 된다. 제목과 부제만 넘겨 봐도 이야기가 이어져야 한다.
- 시간 순서를 인과로 바꾸지 않는다. 허깅페이스 인수 발표(9월)는 Anthropic의 AMD 이식 발표(11월)보다 앞섰으므로 "대응"으로 쓰지 않는다. 두 사건은 구조의 차이로 설명한다.
- 결과를 보고 거꾸로 의도를 붙이지 않는다. 예를 들어 "NVIDIA가 딥러닝을 예측했다"고 쓰지 않는다.
- 전후 비교는 같은 기준으로 한다. "층이 하나 늘었다" 같은 결과 나열만으로는 설득력이 없다. 고객 유지 방식, 취약점, 플랫폼 유형처럼 그 변화가 왜 중요한지를 같은 틀로 보여 준다. 앞에서 쓴 분석 틀(예: 2×2 매트릭스)을 다시 써서 연결한다.

## 7. 사실과 해석을 표시한다

- 회사 공시, 보도, 추정, 발표자 분석에 각각 라벨을 붙인다. 분석에는 근거 사실을 함께 둔다(예: "01 · 분석 / 근거: 개발자 1,200만 명+").
- 단서는 화면이 아니라 대본 메모에 둔다. 범위가 제한된 수치(단일 사례, 회사 자체 발표)는 시사점에 범위를 한 마디로 적는다.

## 8. 수치는 현실적으로 쓰고 근거를 남긴다

- 검증된 수치만 쓴다. 자체 집계와 외부 추정을 구분하고, 기본값은 보수적인 외부 추정으로 한다. 예를 들어 CUDA 개발자는 NVIDIA 자체 집계 1,100만 명이 아니라 외부 추정 약 600만 명을 쓴다.
- 비율, 1인당 금액 같은 파생 수치는 계산식을 대본 메모에 남긴다(예: 6.0% = 129.3 ÷ 2,159).
- 한 수치를 고치면 그 수치를 쓰는 모든 곳을 같이 고친다. 본문, 요약, 대본, 사실 목록이 모두 해당한다.
- 긴 판(20분)은 데이터 중심으로 만들고, 애니메이션 장면을 늘려 시간을 채우지 않는다. 짧은 판(5분)도 핵심 구조는 빼지 않는다.

## 9. 출처를 표기한다

- 참고자료 장에 불렛으로 모은다. 디자인 참고 자료와 인용한 덱도 등록한다.
- 장마다 하단에 아주 작은 각주를 둔다. 본문이 몰입을 해치지 않을 만큼 흐리게 한다.

## 10. 시각 자료 (발표 자료)

- 레퍼런스 덱의 디테일에 맞춘다.
  - 회색 부제
  - 카드: #151515 바탕, #2D2D2D 테두리, 상단 녹색 바
  - 강조 상자: 옅은 녹색 바탕
  - 숫자: Inter
  - 배경: 은은하게. 형광색은 남용하지 않는다.
- 이미지는 의미가 있을 때만 쓴다. 한 번 쓴 이미지는 재사용하지 않는다.
- 애니메이션은 상태 변화를 설명할 때만 쓴다. 장식용 움직임은 넣지 않는다.
- 컨설팅 문법을 쓴다. 전후 비교 다이어그램, 근거 카드, 수치 카드로 정보 밀도를 확보한다.

## 리뷰 체크리스트

| 질문 | 차단할 문제 |
|---|---|
| 비유 없이 사실로 말하는가? | 검증할 수 없는 은유, 의인화 |
| 제목이 앞 장에서 이어지는가? | 근거 없는 결론, 질문형·극적 제목 |
| 화면 글이 개조식인가? | 서술형 "~다" 문장, 면책·사용 안내 |
| 용어가 업무 용어인가? | 구어·유아적 표현, 번역투 |
| 시간 순서와 인과가 맞는가? | 선후가 다른 사건을 대응 관계로 서술 |
| 사실과 해석이 구분되는가? | 분석을 사실처럼 단정 |
| 수치가 보수적이고 일관적인가? | 자체 집계를 기본값으로 사용, 한 곳만 고친 수치 |
| 출처가 남아 있는가? | 참고자료 누락, 계산식 누락 |
